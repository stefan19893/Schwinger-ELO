# Project Specification: Schwingen ELO Rating Engine (15-Year Historical Analysis)

## 1. Project Overview & Objective
This project builds an automated end-to-end data pipeline and web dashboard to compute historical ELO ratings for Swiss Schwingen athletes ("Schwinger") covering the last 15 years (2011–present).

The application will:
1. Scrape and parse match-level historical results from publicly available archives (`schlussgang.ch` / `esv.ch`).
2. Clean, deduplicate, and normalize athlete identities into a structured SQLite/Parquet database.
3. Compute tailored ELO ratings accounting for Schwingen-specific dynamics (draws/"Gestellt", grades/notes from 8.25 to 10.00, festival weights).
4. Generate a static, responsive web application hosted free on **GitHub Pages** (via GitHub Actions workflow), complete with interactive search, historical charts, and leaderboards.
5. Run **fully locally with one command** (`./scripts/deploy_local.sh`): set up the environment, run the pipeline, build the site, and serve it at `http://localhost:8000` — without GitHub.

**Guiding principle:** local runs and GitHub Actions call the **same CLI** (`python -m src.cli …`). The workflows add nothing that cannot be reproduced locally.

---

## 2. Tech Stack & Architecture

- **Language:** Python 3.11+
- **Data Scraping & Ingestion:** `httpx`, `tenacity` (retry logic), `tqdm`, `pypdfium2` (text of the statistic PDFs); `BeautifulSoup4`/`selectolax` available for HTML if needed (the festival index is a JSON:API)
- **Data Storage:** SQLite (local intermediate staging) + Parquet (or DuckDB) for fast analytics
- **Modeling & Processing:** `pandas`, `numpy`, `scipy`
- **Frontend:** static HTML + TailwindCSS + Apache ECharts, reading precomputed JSON bundles generated by Python (`athletes.json`, `rankings_latest.json`, `history_<id>.json`). No backend, no Node build step required.
- **Entry point:** a single CLI, `src/cli.py`, exposing each pipeline stage as a subcommand.
- **Local run:** `scripts/deploy_local.sh` (bash; Linux, macOS, WSL) — wraps setup + CLI + local web server.
- **Automation & Hosting:** GitHub Actions (scheduled crawler & builder) + GitHub Pages.

## 4. Pipeline Details

### 4.1 Data Scraping & Normalization
- **Source Target:** schlussgang.ch only (user decision 2026-09-29; esv.ch is not crawled — its terms forbid it). Festival index: the JSON:API `backend-api.schlussgang.ch/jsonapi/node/event`. Bouts: the per-festival "Statistische Tabelle" PDFs linked from each event (one line per athlete and Gang: `+` win / `-` gestellt / `o` loss, opponent, grade); every bout appears twice and is built by pairing both entries.
- **Politeness:** respect robots.txt/terms, 0.5–1.0 s delay between requests, descriptive User-Agent, retries with backoff, every response cached in `data/raw/` and never re-fetched unless `--refresh` is given.
- **Data Entity Schema:**
  - `Festival`: `fest_id`, `name`, `date`, `category` (ESAF, Bergkranz, Teilverband, Kantonal, Gauverband, Regional), `location`.
    - Category `ESAF` is the tier of all festivals with eidgenössischem Charakter (eidgenössischer Kranz): the ESAF itself, Kilchberger Schwinget, Unspunnen-Schwinget and ESV Jubiläumsschwingfeste. The column `eidg_type` (`ESAF`, `Kilchberg`, `Unspunnen`, `Jubilaeum`) tells them apart. `Bergkranz` = the six Bergkranzfeste (Brünig, Rigi, Schwägalp, Schwarzsee, Stoos, Weissenstein); Berg festivals without a Kranz are `Regional`.
    - Tier lists are backed by the user-supplied reference `src/scraper/reference/schwingfeste_schweiz.json` (the crawler warns on disagreements).
  - `Bout` (Gang): `bout_id`, `fest_id`, `gang_nr` (1–6, or 1–8 at ESAF), `athlete_a_id`, `athlete_b_id`, `outcome` (`WIN_A`, `WIN_B`, `DRAW`), `grade_a`, `grade_b`.
    - Grades are 8.25–10.00. A grade is NULL only for an **extra bout** (Zusatzgang: with an odd field one athlete fights one bout more than the festival has Gänge; his sheet line shows 0.00 / 0.25 / no grade — flag `extra_bout`) or a line printed without grade (flag `grade_missing`); enforced by a CHECK (user decision 2026-10-01). Injury/forfeit bouts (`u`, `> unfall`, 0.00 in a regular Gang) are not bouts.
    - Extra columns: `flags` (e.g. `extra_bout`, `gang_inferred`, `gang_collision`) and `schlussgang` (1/0 only where the sheet marks it, else NULL = unknown).
  - `Athlete`: `athlete_id`, `full_name`, `club` (Schwingklub), `sub_association` (BKSV, ISV, NOSV, NWSV, SWSV), `active_years`.
- **Handling Ambiguity:** Match keys must resolve athlete collisions (e.g., duplicate names) using Schwingklub and unique profile slug URLs.

### 4.2 Schwingen-Specific ELO Model Specifications
Standard chess ELO must be calibrated with the following domain parameters:

1. **Draw Handling ("Gestellt"):**
   - Result value $S \in \{1.0, 0.5, 0.0\}$.
   - In Schwingen, draws occur in roughly 20–35% of bouts, especially among elite "Eidgenossen". Expected score formula remains:
     $$E_A = \frac{1}{1 + 10^{(R_B - R_A) / 400}}$$
2. **Grade / Margin of Victory (MoV) Multiplier:**
   - Notes range from $8.25$ to $10.00$.
   - A maximum victory (Plattwurf $10.00$ vs $8.50$ / $8.75$) carries higher conviction than a minimal victory ($9.75$ vs $8.75$).
   - Multiplier $\lambda = 1.0 + \alpha \cdot (\text{Grade}_A - \text{Grade}_B - \text{BaselineDiff})$.
   - Bouts with a NULL grade (extra bouts, `grade_missing`) count with their outcome only: no MoV multiplier ($\lambda = 1$).
3. **Festival Weighting ($K$-Factor Modulation):**
   - Eidgenössische Feste — ESAF (Eidgenössisches Schwing- und Älplerfest), Kilchberger Schwinget, Unspunnen-Schwinget, ESV Jubiläumsschwingfest: $K = 48$
   - Bergkranzfeste (Brünig, Rigi, Schwägalp, Schwarzsee, Stoos, Weissenstein): $K = 40$
   - Teilverbandsfeste: $K = 32$
   - Kantonal- and Gauverbandsfeste (one Kranzfest tier): $K = 24$
   - Regional-/Rangschwinget and Bergschwinget without Kranz: $K = 16$
4. **Seasonality & Inactivity Decay:**
   - At the beginning of each season (April), apply Mean Reversion:
     $$R_{t+1} = R_t \cdot (1 - \delta) + R_{\text{mean}} \cdot \delta \quad (\text{with } \delta \approx 0.10, R_{\text{mean}} = 1500)$$
   - Athletes inactive for $> 1.5$ seasons receive provisional status flags.

All model parameters live in `src/config.py` so they can be tuned without code changes.

## 5. Command-Line Interface (`src/cli.py`)

Every stage is idempotent and incremental: re-running only processes what is new, using the cache in `data/raw/`.

| Command | Does |
|---|---|
| `python -m src.cli crawl` | Discover festivals and download their statistic PDFs (options: `--from-year`, `--to-year`, `--refresh`, `--offline`, `--no-pdfs`) |
| `python -m src.cli parse` | Parse cached statistic PDFs (offline) into SQLite `bouts` / `athletes_raw` / `parse_rejects` (`--force` to re-parse) |
| `python -m src.cli clean` | Identity resolution → `data/processed/*.parquet` |
| `python -m src.cli elo` | Compute ratings → `data/processed/ratings.parquet` |
| `python -m src.cli build` | Write the static site to `dist/` |
| `python -m src.cli all` | `crawl → parse → clean → elo → build` |
| `python -m src.cli serve` | Serve `dist/` at `http://localhost:8000` (`--port`) |

Global options:
- `--sample`: use the committed offline dataset in `tests/fixtures/sample/` instead of the network. The full pipeline finishes in well under a minute. Outputs go to `data/sample/` (unless `--data-dir` is given) so a sample run never overwrites real data.
- `--data-dir`: use a different data directory.
- `--skip-crawl`: in `all`, use only data that is already cached.

Configuration precedence: CLI flag > environment variable (`SCHWINGEN_*`) > defaults in `src/config.py`.

## 6. Local Run & Quick Deploy (`scripts/deploy_local.sh`)

One command takes a fresh clone to a running site:

```bash
./scripts/deploy_local.sh            # full/incremental real-data run, then serve
./scripts/deploy_local.sh --sample   # offline demo with the sample dataset (fast)
```

### 6.1 Steps performed
1. **Preflight:** check for Python ≥ 3.11 and fail with a clear message otherwise.
2. **Environment:** create `.venv/` if it is missing. Reinstall `requirements.txt` only when its hash has changed (stored in `.venv/.requirements.sha256`).
3. **Tests (optional):** run `pytest -q` when `--test` is given. Abort on failure.
4. **Pipeline:** run `python -m src.cli all`, passing the flags through.
5. **Serve:** run `python -m src.cli serve --port <port>` and print the URL. Stop with Ctrl+C.

### 6.2 Flags
| Flag | Effect |
|---|---|
| `--sample` | Offline demo data, no network |
| `--skip-crawl` | Rebuild from already cached/processed data only |
| `--refresh` | Re-fetch pages even if cached |
| `--test` | Run the test suite before building |
| `--no-serve` | Build only, don't start the server |
| `--port N` | Server port (default 8000) |

### 6.3 Requirements
- `set -euo pipefail`. Every step prints a short header. The script exits non-zero on the first failure.
- It can be run from any working directory (it resolves the repo root itself) and is safe to re-run at any time.
- A full first real-data crawl takes a long time because of the politeness delays. The script warns about this, shows progress (`tqdm`), and can be interrupted and resumed because all fetched pages are cached.
- The site uses only relative URLs, so it works both at `localhost:8000/` and under the GitHub Pages sub-path `/Schwinger-ELO/`.

## 7. GitHub Pages Deployment Strategy

Since GitHub Pages serves static files only:
1. **Build Step (`python -m src.cli build`):**
   - Outputs a lightweight static directory (`dist/`).
   - Pre-calculates top 200 all-time ratings, active rankings, peak career ratings, and peak ELO per season.
   - Saves compact JSON search indices (chunked by initial letters if large).
   - Generates individual lightweight JSON datasets per athlete to enable on-demand chart loading without downloading 15 years of raw data.
2. **GitHub Actions Workflow** (uses the same CLI as local runs):
   - Installs dependencies.
   - Runs tests.
   - Executes the incremental data update: `python -m src.cli all`.
   - Uses `actions/deploy-pages@v4` to publish `dist/` directly.
