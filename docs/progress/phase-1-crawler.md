# Phase 1 — Festival crawler (Milestone 1)
**Status:** in review (all tasks done 2026-09-29; phase-reviewer not yet run)
**Agent:** data-engineer

## Goal
Discover every festival 2011–present and persist it in SQLite.

## Exit criteria
- `src/scraper/client.py`: rate-limited (0.5–1.0 s), retrying (`tenacity`), disk-cached HTTP client.
- `src/scraper/fests_crawler.py` fills a `festivals` table matching the `Festival` schema in the spec.
- Festival `category` mapped to the spec's categories (ESAF, Bergkranz, Teilverband, Kantonal, Gauverband, Regional).
- `python -m src.cli crawl` wired up (`--from-year`, `--to-year`, `--refresh`).
- Tests run offline against fixtures in `tests/fixtures/`.

- 2026-09-29 — **Phase-reviewer passed; review findings fixed** (user asked to fix before the PR; no network requests made):
  1. **Year rollover (must-fix):** a year's listing is no longer cached forever just because the year is in the past. `client.get(..., max_age, final_after)`: a cached copy counts as fresh if it is younger than `max_age` **or** was fetched after `final_after`; the crawler sets `final_after = Dec 31 of that year + listing_final_grace_days` (Config, default 60) and `max_age = listing_max_age_hours` (24 h) for every year. So a listing cached during its season is re-fetched (at most daily) until one copy was fetched after the grace period, then it is final. Existing `data/raw` cache (fetched 2026-09-29) is already final for 2011–2025; 2026 refreshes daily until 2027-03-01. Tests with a fake UTC clock (`utcnow` is now injectable in `HttpClient`) cover the whole timeline.
  2. **Delay floor:** `MIN_REQUEST_DELAY = 0.5` in `src/config.py`; `load_config` rejects `request_delay_min < 0.5` (exit 2 via CLI) and `HttpClient` enforces it too. CLI crawl tests now use the real floor with `time.sleep` patched (client looks `time.sleep` up at call time).
  3. **Retry-After:** parsed on 429/503 (and other retryable 5xx) as delta-seconds or HTTP-date, capped at `retry_after_max` (Config, 300 s); the backoff wait is `max(exponential backoff, Retry-After)`, and the 0.5–1.0 s throttle still applies afterwards, so it is never below the normal delay. Invalid/past values are ignored.
  4. **Socket guard:** `tests/conftest.py` now also patches `socket.socket.connect`/`connect_ex` — only loopback (127.0.0.0/8, ::1, "localhost") and AF_UNIX allowed; httpx guard kept. Tests prove remote IPv4/IPv6/hostname connects raise and loopback works.
  5. **`crawl --offline`** (global option scoped to crawl/all, env `SCHWINGEN_OFFLINE`): cache-only; stale cached copies are served, uncached queries are listed in `CrawlReport.cache_misses`, logged, and the command exits 1; never fetches. `--offline` + `--refresh` is a config error. Verified against the real cache: `crawl --offline` → 0 requests, 106 cache hits, rc 0; `--from-year 2010 --to-year 2010 --offline` → 5 misses reported, rc 1.
  6. Phase 2 risks from the review logged in `phase-2-parser.md` → "Known risks from Phase 1 review".
