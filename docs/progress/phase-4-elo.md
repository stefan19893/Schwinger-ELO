# Phase 4 — ELO engine (Milestone 3b)
**Agent:** elo-modeler

## Goal
`SchwingElo` engine implementing spec §4.2 with full rating history.

## Exit criteria
- `src/pipeline/elo_engine.py`: expected score, draws (S=0.5), MoV multiplier, festival K-factors, April mean reversion (δ≈0.10, mean 1500; implemented with δ = 0.05 and all K-factors x 2 since the decision of 2026-10-03), provisional flag after >1.5 inactive seasons.
- Bouts processed in chronological order, festival by festival: festivals in order `(date, fest_id)`, all bouts of a festival scored against the pre-festival ratings (`elo_update_mode = "festival"`); deterministic output. *(Reworded 2026-10-03; originally "(date, then gang_nr)". Reason: the Gang numbers are unreliable for ~2 % of the bouts, the festival-wise update is exactly independent of them and predicts as well as the bout-by-bout order on equal information — test Brier 0.1126 vs 0.1129 at the current K; confirmed with the Phase 4 sign-off. `gang_nr` is still part of the sort key and the bout-by-bout order remains selectable as `sequential`.)*
- `alpha` and `BaselineDiff` chosen with documented reasoning in `STATE.md` Decisions.
- `tests/test_elo.py`: unit tests for each rule + sanity tests on real data (elite athletes such as Glarner, Wicki, Reichmuth, Forrer rank near the top in their peak seasons).
- Parameters live in `src/config.py`.
- `python -m src.cli elo` writes `data/processed/ratings.parquet` (athlete, date, fest_id, rating_before, rating_after); works with `--sample`.
